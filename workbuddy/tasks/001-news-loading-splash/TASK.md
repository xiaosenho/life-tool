# 任务 001：今日新闻加载开屏动画

> 状态：已被任务 002 替代，请勿执行。本任务错误地把启动动画与今日新闻加载绑定。

## 负责人

WorkBuddy

## 背景

首页“今日精选”通过 `newsService.getTopNews()` 请求 `/news/top`。当前请求在 `frontend/app/(tabs)/index.tsx` 的 `useFocusEffect` 中才开始，网络或服务端缓存较慢时，用户进入首页后会长时间看到“加载中”或空白新闻区域。

本任务不是单纯增加一个固定时长动画，而是利用启动动画覆盖新闻首轮预取时间，并把预取结果交给今日页复用，避免动画结束后再次请求同一接口。

## 目标体验

1. 已登录用户冷启动进入主界面时，显示轻量、现代的 App 内开屏动画。
2. 动画文案围绕“正在准备今日精选”，风格简洁，不使用夸张插画。
3. 动画出现后立即并行加载今日新闻，不阻塞数据库初始化、登录恢复等已有流程。
4. 新闻加载完成且最短展示时间结束后，动画平滑淡出。
5. 新闻加载太慢或失败时不得无限阻塞，达到最长展示时间后进入首页。
6. 今日页优先使用开屏阶段取得的新闻结果，不重复发起首轮请求。
7. 后续从其他 Tab 返回今日页时仍可正常刷新新闻。

## 推荐交互参数

- 最短展示：800～1000ms。
- 最长等待：3000ms。
- 退出动画：180～260ms 淡出。
- 动画元素：新闻卡片轮廓、轻微上下浮动或三点加载；优先使用 React Native `Animated` 和 `Ionicons`。
- 不新增 Lottie 或其他原生动画依赖，除非能说明必要性并获得确认。
- 使用当前主题的 `colors.background`、`colors.surface`、`colors.accent`、`colors.text` 和 `colors.muted`，三套主题均需协调。

## 推荐实现结构

可以调整文件结构，但应保持职责清晰。建议：

- `frontend/src/store/newsBootstrapStore.ts`
  - 保存启动预取状态：`idle/loading/success/error`。
  - 保存首轮新闻列表和是否已消费。
  - 提供去重的 `prefetch()`，并避免并发重复请求。
- `frontend/src/components/NewsLoadingSplash.tsx`
  - 只负责动画和展示，不直接耦合页面路由。
  - 支持淡出完成回调。
- `frontend/app/_layout.tsx`
  - 登录恢复完成且用户已认证后触发一次新闻预取。
  - 在 Stack 上方展示 App 内开屏层。
  - 未登录用户不应因新闻请求停留在开屏层。
- `frontend/app/(tabs)/index.tsx`
  - 首次进入时消费预取数据。
  - 已有 `loadNews()` 保留为刷新/回焦兜底，但不得与正在进行的预取重复请求。

不强制使用 Zustand；如果使用其他简单方案，也必须满足请求去重和页面复用。

## 状态与异常边界

- 无登录态：不请求新闻，不展示新闻开屏动画。
- 请求成功但返回空数组：正常进入首页，今日页展示已有空态。
- 请求失败：记录警告并进入首页，不弹阻塞式错误提示。
- 超过最长等待：隐藏动画，后台请求可继续；请求完成后今日页应能更新。
- 组件卸载：清理所有 timer 和 Animated listener，避免卸载后更新状态。
- 开发环境 React Strict Mode 下不得产生两次新闻请求。
- 不要调用或控制原生 `expo-splash-screen` 来长时间阻塞启动；本任务使用 React 树内的启动覆盖层。

## 视觉要求

- 画面保持留白，中心内容宽度适合手机屏幕。
- 推荐结构：小型新闻图标/卡片动画 + “今日精选”标题 + 一行加载文案。
- 不显示虚假百分比进度。
- 不使用大面积渐变、复杂阴影或高频闪烁。
- 适配 Android 手势导航、三键导航和安全区。
- Web 端可正常渲染，不依赖仅原生可用的动画 API。
