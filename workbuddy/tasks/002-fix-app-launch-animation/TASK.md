# FIX 任务 002：修正为 App 启动加载动画

## 负责人

WorkBuddy

## 修正说明

任务 001 的“启动阶段预取今日新闻”方向可以保留，但动画的产品语义和展示时机需要修正：

- 它是 **App 打开时的启动加载动画**，不是进入今日页后出现的“新闻加载动画”。
- 它应从 App 冷启动阶段开始展示，覆盖数据库、登录态恢复和首页数据准备过程。
- 对已登录用户，启动期间并行加载今日新闻，用启动动画遮住新闻接口较慢造成的首屏等待。
- 动画视觉和文案保持通用，不出现“加载新闻”“今日精选正在加载”等业务提示。

## 目标体验

1. 用户打开 App 后立即看到统一、品牌化的启动动画，不出现空白画面。
2. SQLite 初始化、登录态恢复和 Token 刷新照常进行，不被动画阻塞。
3. 确认用户已登录后，立即并行预取今日新闻。
4. 已登录用户在“最短展示时间结束且新闻已就绪”后进入主界面。
5. 新闻请求过慢或失败时，达到最长等待时间后仍进入主界面，不能卡在启动页。
6. 今日页复用启动阶段取得的新闻数据，避免打开首页后重复请求。
7. 未登录用户不请求新闻；基础初始化完成且满足最短展示时间后进入登录页。

## 时间规则

- 最短展示时间：800～1000ms，从 App 启动动画首次挂载开始计算。
- 新闻最长等待：约 3000ms；超时后动画退出，新闻请求可以在后台继续。
- 退出动画：180～260ms 淡出。
- 不使用固定长时间假加载，不因新闻失败阻止用户进入 App。

## 视觉要求

- 这是 App 级启动画面，使用 LifeTool 图标、名称或抽象生活管理元素。
- 文案保持通用，例如“整理今天，准备出发”。
- 不显示“今日精选”“正在加载新闻”等新闻业务文案。
- 不显示虚假百分比。
- 简洁、现代、留白充足；使用现有主题语义色。
- 使用轻微呼吸、圆环或三点动画，避免高频闪烁和大幅移动。
- 适配 Android 手势导航、经典三键导航、安全区和 Web。

## 状态边界

- 未登录：不请求新闻，基础初始化完成后退出动画并进入登录页。
- 已登录且新闻成功：最短时间结束后淡出并进入首页，首页直接使用预取数据。
- 新闻返回空数组：视为请求完成，正常进入首页并显示既有空态。
- 新闻失败：记录警告，在最短展示时间后即可退出；不得弹阻塞提示。
- 新闻超时：最长约 3000ms 后退出，后台完成后今日页应能更新。
- Token 恢复失败：沿用现有认证规则进入登录页，不继续等待新闻。
- 开发环境 Strict Mode 下不得产生两次新闻请求。
- 所有 timer、Animated loop、listener 和 store subscription 都必须在卸载时清理。
